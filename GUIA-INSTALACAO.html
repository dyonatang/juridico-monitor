Guia de instalação

Do zero ao sistema no ar, com o Claude conectado. São 8 etapas; faça na ordem. O que é clicável no site está em negrito; o que é para digitar está em código.

Etapas
  1. Criar o projeto no Firebase
  2. Criar o banco (Firestore)
  3. Baixar a chave de acesso
  4. Rodar no seu computador
  5. Subir o código para o GitHub
  6. Publicar (App Hosting)
  7. Agendar a verificação automática
  8. Conectar o Claude (MCP)

Antes de começar

2 min
  • Uma conta Google (Gmail) — será a dona do projeto.
  • Uma conta no github.com (gratuita). Se não tiver, crie antes da etapa 5.
  • Um cartão de crédito para o plano Blaze do Firebase (etapa 1). É pague-pelo-uso; para este volume a conta fica perto de zero — o Firestore e o App Hosting têm cota gratuita mensal.
  • Dentro da pasta do projeto existe um arquivo .env.example — na etapa 4 você vai copiá-lo para .env.local e preencher com os dados do seu Firebase (ele não vem pronto; cada instalação tem os seus próprios tokens).

1. Criar o projeto no Firebase

navegador

  1. Abra console.firebase.google.com e entre com a conta Google.

  2. Clique em Criar um projeto (ou Adicionar projeto). Nome: juridico-monitor. Avance.

  3. Na pergunta sobre o Google Analytics, desative (não é necessário). Clique em Criar projeto e espere terminar. Clique em Continuar.

  4. No canto inferior esquerdo aparece Spark · Fazer upgrade. Clique, escolha Blaze (pague conforme o uso), associe ou crie uma conta de faturamento com o cartão e confirme. Pode definir um alerta de orçamento (ex.: R$ 20) — recomendo.

    Sem o Blaze o App Hosting (etapa 6) não funciona. Este é o único passo com cartão.

Você está dentro do projeto e o rodapé mostra "Blaze".

2. Criar o banco (Firestore)

navegador

  1. No menu esquerdo: Criação (Build) › Firestore Database › Criar banco de dados.

  2. Edição: Standard. ID do banco: deixe (default).

  3. Local: southamerica-east1 (São Paulo). Isso não pode ser mudado depois. Avance.

  4. Regras de segurança: Modo de produção. Clique em Criar.

  5. Ainda em Criação: Storage › Começar › modo produção › mesma região › Concluído. É onde os PDFs importados ficam guardados.

Abre a tela do banco, vazia. As coleções aparecem sozinhas no primeiro cadastro.

3. Baixar a chave de acesso

navegador + pasta

  1. Clique na engrenagem ao lado de "Visão geral do projeto" › Configurações do projeto.

  2. Aba Contas de serviço. Com "Firebase Admin SDK" selecionado, clique em Gerar nova chave privada › Gerar chave. Baixa um arquivo .json.

  3. Renomeie o arquivo para firebase-key.json e mova para a pasta do projeto (juridico-monitor, a mesma onde está o package.json).

    Esse arquivo dá acesso total ao banco. Ele já está no .gitignore — não vai para o GitHub. Não envie por WhatsApp/e-mail.

4. Rodar no seu computador

terminal5 min

  1. Abra a pasta do projeto no Explorador de Arquivos. Na barra de endereço digite cmd e Enter — abre o terminal já dentro da pasta.

  2. No terminal, instale as dependências e crie o seu .env.local a partir do exemplo:

    npm install
copy .env.example .env.local

  3. Gere 5 tokens aleatórios, um de cada vez (rode o comando 5 vezes e copie cada resultado):

    node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

    Abra o .env.local no Bloco de Notas e cole um token em cada uma destas linhas, sem repetir: SESSION_SECRET, MCP_TOKEN, CRON_SECRET, WEBHOOK_SECRET, INGEST_TOKEN. Troque também DASHBOARD_USER (seu usuário de login) e DASHBOARD_PASSWORD (sua senha). Salve.

  4. Leitura de PDF por IA (recomendado): em console.anthropic.com › API keys › Create key. Copie a chave (começa com sk-ant-) e, no .env.local, troque a linha # ANTHROPIC_API_KEY=sk-ant-... por ANTHROPIC_API_KEY= + a chave (sem o #). Coloque uns US$ 10 de crédito na conta — cada PDF custa centavos.

    Sem essa chave a tela "Importar PDF" ainda funciona, mas só extrai o número do processo do texto; não lê PDF escaneado nem faz resumo.

  5. Ainda no terminal:

    npm run dev

  6. Abra http://localhost:3000. Aparece a tela de login: use o DASHBOARD_USER e o DASHBOARD_PASSWORD que você definiu no .env.local.

  7. Teste: CPFs / CNPJs › cadastre um. Depois Processos › cole o número de um processo real (formato 0000000-00.0000.0.00.0000) › Cadastrar e consultar. Em alguns segundos ele importa as movimentações do DataJud.

  8. Teste o leitor: Importar PDF › arraste uma citação ou petição › Enviar e ler. Ele mostra o resumo, o(s) processo(s) encontrado(s) e já cadastra os que não existiam.

    Se der "Não foi possível conectar ao Firebase", confira o nome/local do firebase-key.json. Se der "Processo não encontrado na fonte", o tribunal ainda não publicou esse processo no DataJud — tente outro número.

  9. Para parar: Ctrl + C no terminal.

Painel abre, empresa e processo cadastrados, movimentações visíveis no detalhe do processo.

5. Subir o código para o GitHub

navegador + terminal

  1. Em github.com › + › New repository. Nome juridico-monitor, Private. Não marque nenhuma opção de README. Create repository.

  2. Copie a URL que aparece (termina em .git).

  3. No terminal, dentro da pasta do projeto (troque a URL pela sua):

    git init -b main
git add .
git commit -m "Juridico Monitor"
git remote add origin https://github.com/SEU-USUARIO/juridico-monitor.git
git push -u origin main

    Na primeira vez o Git pede para entrar no GitHub — autorize na janela que abre.

Atualize a página do repositório: os arquivos aparecem. .env.local e firebase-key.json não aparecem (correto).

6. Publicar (Firebase App Hosting)

navegador + terminal15 min

  1. Instale a ferramenta de linha de comando e entre na conta:

    npm install -g firebase-tools
firebase login
firebase use SEU-ID-DE-PROJETO

    Troque SEU-ID-DE-PROJETO pelo ID do projeto que você criou na etapa 1 — está em Configurações do projeto (pode ter um sufixo, ex.: juridico-monitor-a1b2c; use o ID completo).

  2. Crie os segredos (um comando por vez; ele pede o valor — cole o mesmo que está no .env.local). Quando perguntar se deve conceder acesso ao backend, responda Y.

    firebase apphosting:secrets:set DASHBOARD_USER
firebase apphosting:secrets:set DASHBOARD_PASSWORD
firebase apphosting:secrets:set MCP_TOKEN
firebase apphosting:secrets:set CRON_SECRET
firebase apphosting:secrets:set WEBHOOK_SECRET
firebase apphosting:secrets:set SESSION_SECRET
firebase apphosting:secrets:set ANTHROPIC_API_KEY

  3. No console: Criação › App Hosting › Começar.

  4. Região: southamerica-east1 se estiver na lista; senão us-central1. Avance.

  5. Conectar ao GitHub › autorize o app do Firebase na sua conta › escolha o repositório juridico-monitor. Diretório raiz: /. Branch ativa: main. Marque "implantação automática". Avance.

  6. ID do backend: juridico. Concluir e implantar. A primeira publicação leva uns 5–8 minutos.

  7. Quando terminar, copie o domínio mostrado (algo como juridico--juridico-monitor.southamerica-east1.hosted.app).

  8. Abra apphosting.yaml no Bloco de Notas, troque https://SEU-BACKEND.web.app pelo domínio copiado (com https://). Salve e publique a mudança:

    git add apphosting.yaml
git commit -m "URL do app"
git push

  9. Publique as regras que bloqueiam acesso direto ao banco:

    firebase deploy --only firestore:rules

Abra o domínio no celular: pede usuário/senha e mostra o painel com a empresa e o processo que você cadastrou na etapa 4.

Em App Hosting › seu backend › Configurações › Domínios dá para ligar um domínio próprio, ex.: juridico.caranguejodoassis.com.br.

7. Agendar a verificação automática

navegador

  1. Abra console.cloud.google.com (mesma conta). No topo, selecione o projeto juridico-monitor.

  2. Na busca do topo digite Cloud Scheduler e abra. Se pedir para ativar a API, ative.

  3. Criar job. Nome: sincronizar-processos. Região: southamerica-east1. Frequência: 0 6,12,18 * * *. Fuso horário: Brasília (America/Sao_Paulo). Avance.

  4. Tipo de destino: HTTP. URL: https://SEU-DOMINIO/api/cron/sync?secret=COLE_O_CRON_SECRET (o valor está no .env.local). Método: GET. Avance › Criar.

  5. Na lista, clique em Forçar execução para testar. Volte ao painel do sistema: "Última sincronização" deve mostrar a hora de agora.

Três verificações por dia (6h, 12h, 18h). Os 3 primeiros jobs do Scheduler são gratuitos.

8. Conectar o Claude (MCP)

Claude

  1. Monte a URL do conector: https://SEU-DOMINIO/api/mcp?token=COLE_O_MCP_TOKEN.

  2. No Claude (app ou claude.ai): Configurações › Conectores › Adicionar conector personalizado. Nome: Jurídico. URL: a de cima. Salvar. (Não precisa de OAuth.)

  3. No Claude Code (terminal):

    claude mcp add --transport http juridico "https://SEU-DOMINIO/api/mcp" --header "Authorization: Bearer COLE_O_MCP_TOKEN"

  4. Teste numa conversa: "Use o conector Jurídico e me dê o resumo geral." O Claude deve responder com as contagens do painel.

  5. Para ser avisado todo dia: crie uma tarefa agendada no Claude (ex.: 08:00) com o texto:

    Chame alertas_pendentes no conector Jurídico. Se houver alertas, me envie um resumo claro (processo, data, o que aconteceu) e depois chame marcar_alertas_lidos. Se não houver, responda só "Sem novidades".

A partir daqui você pode cadastrar tudo por conversa: "cadastre o CNPJ 00.000.000/0001-00 da empresa X", "adicione o processo 0000000-00…".

Guarde o MCP_TOKEN como uma senha: quem tiver a URL com o token lê e cadastra processos.

Opcional, depois

  • Descobrir processos pelo CNPJ/CPF automaticamente: contratar a API da Judit (judit.io/planos-api). Com a chave em mãos: firebase apphosting:secrets:set JUDIT_API_KEY, descomente as linhas da Judit no apphosting.yaml, git push. Depois, em CPFs / CNPJs, clique em Ativar em cada documento.
  • Domínio do bucket diferente: se o Storage mostrar um nome que não termina em .firebasestorage.app, adicione FIREBASE_STORAGE_BUCKET=<nome> no apphosting.yaml/.env.local.
  • E-mail a cada alerta: conta em resend.com › chave › firebase apphosting:secrets:set RESEND_API_KEY e descomente NOTIFY_EMAIL_TO no apphosting.yaml.
  • WhatsApp: um fluxo no n8n/Make ou uma instância Z-API/Evolution recebendo o NOTIFY_WEBHOOK_URL.
